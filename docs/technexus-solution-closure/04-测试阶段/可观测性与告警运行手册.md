# TechNexus 可观测性与告警运行手册

## 1. 目标与边界

本手册对应 `TNX-GATE-006`、`NFR-OBS-01` 和 `AC-010`。应用提供 JSON 控制台日志、请求关联 ID、liveness/readiness、Prometheus 指标以及仓库内告警规则。详细指标端点仍受 operations/admin 授权保护；健康探针不返回依赖详情。

本机成功只证明实现和采集面可工作。候选环境仍必须证明 Prometheus 入库、仪表盘查询、告警触发、Alertmanager 通知送达和恢复通知；慢 SQL、主机磁盘和备份状态来自应用外部，不能用本机应用指标冒充。

## 2. 接入

1. 通过反向代理仅向监控网段开放 `/actuator/prometheus`，使用短期 operations/admin Bearer Token；公网只保留无需详情的 `/actuator/health/liveness` 与 `/actuator/health/readiness`。
2. Prometheus scrape job 使用 `job_name: technexus-server`，加载 `ops/prometheus/technexus-alerts.yml`，部署前以目标版本 `promtool check rules` 校验。
3. JSON 日志采集器解析 `@timestamp`、`level`、`logger_name`、`message`、`requestId`、`traceId`。禁止采集 Authorization、Cookie、密码、Token、请求体和查询串。
4. MySQL 开启慢查询日志或 performance_schema，并由 MySQL exporter/日志平台产生慢 SQL、死锁和连接告警；node-exporter 产生磁盘水位告警；`scripts/backup/Test-TechNexusBackupHealth.ps1` 负责备份年龄、Hash 和容量检查及 Webhook。

本机或候选预检命令：

```powershell
$env:TECHNEXUS_METRICS_TOKEN = '<short-lived-token>'
pwsh -File scripts/observability/Test-TechNexusObservability.ps1 `
  -BaseUrl https://candidate.example.com `
  -Classification CANDIDATE_GATE `
  -DiskPath D:\ `
  -OutputPath artifacts/observability/candidate-check.json
```

候选模式拒绝回环 URL。脚本即使数值检查成功，也只输出 `CANDIDATE_REVIEW_REQUIRED`，须完成人工告警闭环证据后才能关闭门禁。

## 3. 告警处置

### target-missing

检查 Prometheus 服务发现、Token、反向代理 ACL 和证书；确认目标不是因配置改名而消失。恢复 scrape 后确认 `up` 连续正常并记录变更。

### instance-down

先查进程、端口、最近部署和 liveness，再以同一 `requestId/traceId` 关联 JSON 日志。不要在未保存现场前盲目重启；恢复后验证 readiness 和核心只读接口。

### database-down

检查 readiness、`technexus_database_ping_seconds`、Hikari、MySQL 进程/连接数/磁盘和最近迁移。数据库不可用时禁止伪造写成功；恢复后验证 Flyway V14、只读和受控写入。

### metrics-stale

检查 `technexus_observability_collection_failures_total`、数据库权限与固定表结构。应用可用但采集过期仍视为监控盲区，不能静默关闭告警。

### http-5xx

按 URI、异常类型和部署版本聚合 5xx，再用响应 `X-Request-Id` 搜索日志。先回滚或隔离新增故障，随后保留触发、处置和恢复时间线。

### hikari-pending

检查慢 SQL、锁等待、连接池上限和连接泄漏；不得仅通过无限增大连接池消除告警。保存 MySQL 慢查询/锁证据和 Hikari 趋势。

### jvm-heap

检查 GC、对象增长和最近流量/发布。连续高水位先限流并保存 heap/GC 证据，再决定重启或修复；不得把重启当作根因关闭。

### queue-failures

按 `queue` 检查文件扫描、AI 建议、批任务或 Outbox 的失败记录和依赖健康；只重试可幂等项。文件扫描失败时文件不得变为可下载。

### queue-backlog

确认生产速率、消费速率、最老任务年龄和依赖延迟。若持续增长，先限制入口并修复消费者；清理任务必须保留审计与逐项结果。

## 4. 候选环境关闭证据

至少保存：环境与版本、Prometheus target 截图/查询、健康探针、真实请求的 `X-Request-Id` 与对应脱敏 JSON 日志、JVM/Hikari/MySQL/队列趋势、慢 SQL 示例、磁盘和备份健康、至少一次告警触发/通知送达/恢复通知、执行人和 UTC 时间。不得在证据中保存 Token、Cookie、密码或用户正文。

当前 `TNX-GATE-006` 只有本机非门禁证据，状态保持 `BLOCKED_EXTERNAL`。
