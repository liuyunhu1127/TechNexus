# 备份恢复本机演练证据（2026-10-29）

关联：`TNX-GATE-003`、`TC-REC-001`、`TST-RISK-002`、`RTM-GAP-003`  
结论：工具链通过；异机门禁未关闭

## 1. 边界

本次只在开发机临时目录和临时 MySQL 8.4.13 实例中演练。脚本输出 `targetClass/sourceClass=LOCAL_TEST_ONLY`、`gatingEvidence=false`，不会把本机其他磁盘或目录冒充异机副本。机器上没有 UNC 映射、云备份变量或可用远端存储工具。

## 2. 数据库基线

- 源库：`technexus_it`，MySQL 8.4.13；
- Flyway：V12；基础表：37；
- binlog：已启用，ROW，保留 2,592,000 秒（30 天）；
- 存储过程、事件和触发器：均为 0；
- 应用账号仅有 `technexus_it.*` 最小业务权限，不能创建任意隔离库。

首次演练因应用账号无 EVENT 权限而拒绝 `mysqldump --events`。随后脚本改为先盘点可编程对象：数量为 0 时显式跳过；数量大于 0 时要求专用备份账号具备对应权限，任何错误均失败关闭，禁止生成静默缺项的备份。

## 4. 隔离恢复结果

使用 `mysqld --initialize-insecure` 启动仅绑定 `127.0.0.1` 随机端口的临时 MySQL 8.4.13，在其中创建 `technexus_restore_rehearsal` 和一次性最小权限恢复账号。从加密副本恢复后验证：

- SHA-256 与 HMAC 均通过；
- Flyway V12 一致；
- 37 张基础表一致；
- `tn_article`、`tn_demand`、`tn_file_object`、`tn_user` 精确行数一致；
- 本机完整脚本恢复耗时 1.74 秒；
- 临时实例正常停止，临时数据目录、明文 SQL、密钥和一次性凭据全部删除。

## 5. 未完成的门禁证据

以下事项只能在真实另一台主机或对象存储上完成：

1. 远端专用账号、传输加密、最小权限、30 个每日点和 12 个月度点策略；
2. 从真实远端副本下载并恢复，而不是从本机临时目录恢复；
3. 调度任务的成功、失败、超过 26 小时和容量低于 20% 告警送达；
4. 记录远端场景的实际 RPO/RTO、执行人、时间和目标主机标识。

因此 `TNX-GATE-003` 继续为 `BLOCKED_EXTERNAL`，`TST-RISK-002`、`RTM-GAP-003` 继续未关闭。
