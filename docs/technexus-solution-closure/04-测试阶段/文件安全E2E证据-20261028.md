## 2. 本轮发现并关闭的问题

1. 污染文件原先只更新数据库 `BLOCKED`，没有移动物理对象。现通过 S3 copy + delete 移至 `quarantine/{fileId}`，数据库同步保存隔离键；
2. 原实现没有联合校验扩展名、MIME 与 Magic Number，也没有 IMAGE 10 MB 护栏。现对白名单类型流式读取最多 8 KiB 识别，并将完整流重放给 ClamAV；
3. 原实现信任对象存储返回的 checksum。现对 ClamAV 实际消费的完整字节同步复算 SHA-256，兼容实现即使错误接受伪造 checksum 也会被隔离；
4. 原 Hash 复用会错误复用 `BLOCKED/SCANNING/UPLOADING` 对象。现仅 `AVAILABLE` 物理对象允许 proof-of-possession 复用；
5. 原实现缺少上传会话过期后的对象清理。现通过带 `CLEANING` 租约状态的 Worker 删除对象，再原子标记会话/未完成文件为 `EXPIRED`，失败则恢复原状态等待重试。

## 3. 可重复 E2E

执行入口：

```powershell
pwsh -File .\scripts\test-file-security-e2e.ps1
```

脚本不保存账号、Token、S3 密钥或恶意样本。ClamAV 重复测试使用仅匹配无害标记的本地 `.ndb` 测试签名；此前另以标准 EICAR 内存流验证真实官方签名，文件 ID `01a182e7-14b7-71c6-bbde-e8b38bc3336c`，状态 `BLOCKED`、对象已移动到 `quarantine/`，样本未落盘。

## 4. 故障注入

| 注入 | 预期 | 结果 |
|---|---|---|
| 停止 clamd 后完成上传 | 文件保持 `SCANNING`、记录失败和重试 | `clamav_unavailable_retry=PASS` |
| 恢复 clamd 并释放下一次扫描时间 | 同一文件恢复到 `AVAILABLE` | `clamav_recovery_to_available=PASS` |
| 上传对象后停止 S3，再调用完成接口 | HTTP 503，幂等预留不缓存 5xx | `s3_unavailable_http_503=PASS` |
| 恢复 S3 后重试完成 | 转为 `SCANNING` 并最终 `AVAILABLE` | `s3_recovery_retry_available=PASS` |

故障注入命令均在 `finally` 中恢复被停止的本机服务；验证结束后临时后端已停止。
