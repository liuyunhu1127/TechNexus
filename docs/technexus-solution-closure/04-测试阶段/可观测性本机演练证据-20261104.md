# TNX-GATE-006 可观测性本机演练证据（2026-11-04）

## 1. 结论

`TNX-GATE-006` 的应用侧本机基础能力通过：请求关联 ID、结构化脱敏日志、liveness/readiness、受保护的 Prometheus 指标、MySQL/队列/JVM/Hikari/HTTP 指标以及告警规则和运行手册均已固化。真实 MySQL 8.4.13 上的探针和指标采集成功，日志未发现测试密码或 Token。

本结果分类为 `LOCAL_OBSERVABILITY_REHEARSAL`、`gatingEvidence=false`。未部署候选 Prometheus/Alertmanager/日志平台，也未证明慢 SQL、磁盘、异机备份告警的通知送达与恢复，因此 `TNX-GATE-006` 保持 `BLOCKED_EXTERNAL`，不得据此放行阶段四。

## 2. 实现与保护边界

- `RequestCorrelationFilter` 校验或生成 8–64 位安全 `X-Request-Id`，写入 MDC 的 `requestId/traceId` 并回显；请求结束清理 MDC；访问日志只记录 method/path/status/duration，不记录查询串、正文、Cookie 或 Authorization；
- Spring Boot 使用 logstash JSON 控制台格式；健康详情固定不公开，liveness/readiness 可供编排器访问，Prometheus 仍走现有 operations/admin 授权；
- `OperationalMetrics` 每 15 秒使用固定 SQL 采集 MySQL 可用性和文件扫描、上传、AI、批处理、Outbox 的有界状态计数，同时暴露最后成功时间、失败计数和 DB ping；
- `ops/prometheus/technexus-alerts.yml` 固化 target/实例、数据库、采集过期、5xx、Hikari、JVM heap、失败队列和积压规则；主机/MySQL 原生/备份指标明确由外部 exporter 或备份健康脚本承担；
- `scripts/observability/Test-TechNexusObservability.ps1` 候选模式拒绝回环 URL，检查探针、必需指标、DB、Hikari 和磁盘，并把成功结果保守标记为 `CANDIDATE_REVIEW_REQUIRED`。
