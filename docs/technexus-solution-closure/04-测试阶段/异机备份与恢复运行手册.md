# TechNexus 异机备份与恢复运行手册

文档编号：`TST-BACKUP-RUNBOOK-001`  
版本：`v0.1`  
关联：`TNX-GATE-003`、`TST-RISK-002`、`RTM-GAP-003`

## 1. 门禁边界

阶段门禁只接受位于另一台主机上的 UNC 共享（`\\backup-host\share`）作为当前脚本的真实异机目标。本机的 C/D/E/F/G/H 盘、SUBST 盘、普通目录或同一物理机上的其他分区都不算异机副本。`-AllowLocalTargetForTest` 仅用于验证脚本，输出会标记 `LOCAL_TEST_ONLY` 和 `gatingEvidence=false`，不能关闭红线。

当前脚本实现 MySQL 逻辑备份、压缩、认证加密、原子复制、远端 SHA-256 回验、备份年龄/容量健康检查和隔离库恢复。凭据从 `TECHNEXUS_DB_*` 或受控凭据文件读取，不写入仓库、清单或控制台。

脚本会先盘点存储过程、事件和触发器。当前 schema 中数量为 0 时显式跳过相应 dump 开关；若将来数量大于 0，则专用备份账号必须具有对应读取权限，任何权限错误都会让备份失败，禁止静默生成不完整副本。

## 2. 目标和权限

1. 在非应用主机创建专用共享和专用账号；应用主机账号只允许创建备份、读取恢复所需文件，不能管理共享主机；
2. 传输层使用 SMB 3 加密或位于受控 VPN 内，关闭 SMB1；
3. 共享启用容量配额、不可变快照或对象锁等防误删能力；
4. 在线保留 30 个每日点，并由目标端生命周期另保留 12 个月度点；删除策略在目标端配置，不让应用主机持有任意历史删除权限；
5. 生成 32 字节随机主密钥，以 Base64 形式保存到 Secret 管理，变量名为 `TECHNEXUS_BACKUP_KEY_BASE64`。密钥必须与备份分开保存并有恢复授权流程。

## 3. 每日备份

```powershell
$env:TECHNEXUS_BACKUP_KEY_BASE64 = '<从 Secret 管理注入，不写入脚本或任务参数>'
pwsh -File scripts/backup/Backup-TechNexusMySql.ps1 `
  -TargetRoot '\\backup-host\technexus' `
  -RetentionDays 30
```

建议由 Windows Task Scheduler 使用专用低权限服务账号每日执行。任务成功标准是退出码 0、JSON 中 `status=SUCCESS`、`targetClass=REMOTE_UNC`、`sha256Verified=true`、`gatingEvidence=true`。清单不含密码、Token 或备份密钥。

## 4. 健康与告警

```powershell
pwsh -File scripts/backup/Test-TechNexusBackupHealth.ps1 `
  -TargetRoot '\\backup-host\technexus' `
  -MaximumAgeHours 26 `
  -MinimumFreePercent 20 `
  -WebhookUri $env:TECHNEXUS_BACKUP_ALERT_WEBHOOK
```

健康检查覆盖：无备份、最近成功点超过 26 小时、备份文件缺失、SHA-256 不一致、容量低于 20% 和容量不可测。正常退出码为 0，异常为 2；Webhook 可接入现有告警平台。定时任务本身的“启动失败/账号失效”也必须由任务调度器告警，不能只依赖脚本内部通知。

## 5. 隔离恢复

先由 DBA 创建只用于演练的 `technexus_restore_*` 数据库并授予恢复账号权限，避免对 `technexus_it` 原库执行覆盖。然后执行：

```powershell
$env:TECHNEXUS_BACKUP_KEY_BASE64 = '<从 Secret 管理注入>'
pwsh -File scripts/backup/Restore-TechNexusMySql.ps1 `
  -ManifestPath '\\backup-host\technexus\2026\10\28\technexus-....manifest.json' `
  -RestoreDatabase 'technexus_restore_20261028'
```

脚本在导入前验证清单 SHA-256 和加密 HMAC，导入后核对 Flyway 版本和基础表数量，并输出关键表估算行数。正式演练还要用 SQL 精确核对关键业务行；完成后由 DBA 独立清理隔离库，恢复脚本默认不删除数据库。

## 6. 证据与 RPO/RTO

每次门禁演练需保存：备份/恢复 JSON、远端清单、加密文件 SHA-256、目标主机标识、执行人、开始/结束 UTC、故障告警截图或事件、Flyway 版本、37 张表和关键业务行的精确比对。Alpha 目标为 RPO 不超过 24 小时、RTO 不超过 4 小时；实际值以最近成功备份时间和完整恢复耗时计算。

## 7. 当前状态

截至 2026-10-29，仓库中没有可识别的 UNC/网络映射、云备份环境变量或远端存储工具。本机只具备 MySQL 8.4.13 工具链。已完成一次本机非门禁演练：真实 `mysqldump --hex-blob`、压缩、AES-256/HMAC、原子复制、SHA-256、健康检查和临时隔离 MySQL 恢复全部通过；恢复为 Flyway V12、37 张表，关键表精确行数一致，本机 RTO 为 1.74 秒。该结果标记为 `LOCAL_TEST_ONLY`、`gatingEvidence=false`。

在用户提供真实非同主机目标、专用权限和告警接收地址前，`TNX-GATE-003` 必须保持 `BLOCKED_EXTERNAL`，`TST-RISK-002` 与 `RTM-GAP-003` 不得关闭。
