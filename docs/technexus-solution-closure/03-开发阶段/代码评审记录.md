## 4. 架构与实现评审

- 工程名严格保持用户确认的 12 个 `technexus-*` 名称，Java 根包为 `com.technexus`，8 个业务模块维持 Domain/API 与 Server Application/Adapter 的依赖方向。
- 生产 Admin 使用 `JdbcAuditTaskRepository`、`JdbcPriceObjectRepository`、`JdbcOperationsRepository`；`InMemory*` 仅由 `test` profile 装配。上一轮 `PlatformApplicationService` 已删除。
- Admin 写端点已改为类型化 DTO 与 Bean Validation；审核领取/决定、定价确认、配置版本冲突和 AI 人工决定具备领域或应用层约束。
- 文件扫描采用 ClamAV INSTREAM，限制 100 MB、设置连接/读取超时；不可用时有界重试，达到阈值后 `BLOCKED`，不会伪造 `AVAILABLE`。
- `ContentApplicationService.submit` 与 `DemandApplicationService.submit` 已创建绑定版本的 AuditTask，并以唯一约束避免同版本重复任务；重试读取现有任务。Admin 决定校验目标版本后在同一事务中推进目标聚合和审核结果，版本失配返回 `AUDIT_TARGET_VERSION_CONFLICT` 且不伪标成功。
- Demand 使用独立 `pending_review_version_id` 表示待审快照；审核通过进入 `APPROVED`，只有 `FREE` 定价确认后发布。`PAID/PREVIEW/ATTACHMENT_PAID` 在 V1 返回 `FEATURE_DISABLED`。
- AI 建议创建后停留 `QUEUED`，没有后台适配器将其推进为 RUNNING/SUCCEEDED/FAILED；接口诚实拒绝对未完成建议作决定，但 AC-007 尚不可验收。

## 5. 安全、数据与并发评审

认证已具备 Argon2id、Token 签名与规范编码、Refresh Hash/轮换/重用撤销、会话实时校验、Origin+CSRF、账号锁定和单节点限流。文件链路已具备对象授权、S3 SigV4、元数据校验与恶意扫描失败关闭。Admin 权限限定为 `admin`/`operations` scope，配置、AI 决定等写入 `tn_operation_audit`。

当前环境没有 Docker、MySQL CLI 或可连接的 MySQL 8.4/ClamAV 服务，所以 V1—V9 migration、跨 Repository 事务、`FOR UPDATE`、乐观锁、扫描协议和重启恢复只完成静态/单元级验证。联系方式字段加密、跨实例限流、后端依赖/密钥扫描及渗透测试也没有证据。
