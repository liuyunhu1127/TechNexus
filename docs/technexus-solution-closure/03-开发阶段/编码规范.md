# 编码规范

版本：`v0.2`  
状态：`评审中`  
技术负责人：TechNexus 技术负责人  
适用语言/版本：Java 21、TypeScript 5.9、SQL（MySQL 8.4）  
适用仓库：`G:\project\TechNexus`

## 1. 目的、范围与优先级

适用于仓库内手写 Java、TypeScript/Vue、SQL、YAML 和测试代码；生成目录、依赖目录和第三方代码不纳入。优先级为：受控设计与 OpenAPI → 本规范 → 自动工具配置 → 社区惯例。例外必须登记编号、风险、批准人与到期日。

## 2. 工程与目录结构

| 路径 | 内容 | 允许依赖 | 禁止依赖 |
|---|---|---|---|
| `technexus-server` | Spring Boot 组合根、Web、安全、适配器 | 8 个业务模块、common | 业务规则堆入 Controller |
| `technexus-{auth,user,community,content,demand,audit,pricing,file}` | DDD 限界上下文 | common、公开 API/事件 | server、Spring、他域 Repository/实体 |
| `technexus-common` | 最小共享内核 | JDK | Spring、业务模块 |
| `technexus-web` | Nuxt 用户端 | `/api/v1` 契约 | 直接数据库访问 |
| `technexus-admin` | Vue/Vite 管理端 | `/api/v1/admin` 契约 | 客户端伪造授权 |

工程名称只允许上述 12 个固定名称；Java 根包必须是 `com.technexus`。

## 3. 命名规范

| 对象 | 规则 | 正例 | 反例 |
|---|---|---|---|
| Java 包 | 小写、根包固定 | `com.technexus.demand.domain` | `com.techNexus` |
| 类型/方法/变量 | PascalCase/camelCase，表达业务语义 | `AuthSession`、`rotateSession` | `DataManager`、`doIt` |
| 常量 | 大写 snake_case | `REFRESH_COOKIE` | `refreshCookie` |
| Maven/npm 工程 | 固定 `technexus-*` | `technexus-server` | `backend` |
| 数据表 | `tn_` + 小写 snake_case + 单数 | `tn_audit_task` | `auditTasks`、`tb_user` |
| 约束/索引 | `pk_`、`uk_`、`fk_`、`ck_`、`ix_` | `uk_user_email` | 自动随机名 |

## 4. 格式与风格

- UTF-8、LF、文件末尾换行；Java 4 空格，TS/Vue 2 空格。
- 禁止通配符导入、未使用导入和 `System.out`；优先不可变对象与小函数。
- TypeScript 开启 `strict`；Java 编译目标使用 `--release 21`。
- Java 由 Spotless Maven Plugin 2.43.0 使用 Eclipse formatter 4.32 统一格式，并在 `verify` 阶段执行 `spotless:check`；TypeScript/Vue 的 ESLint/CI 阻断仍登记为 `DEV-ISSUE-006`。

## 5. 模块和依赖

依赖方向为 `web/adapter → application → domain ← infrastructure`。Controller 只能调用应用服务；domain 不得依赖 Spring/JDBC/Jackson。跨上下文通过公开端口、DTO 或领域事件，不共享 Mapper/Repository。新增依赖必须锁定版本、说明用途、许可证和漏洞结果。

## 6. API与数据模型实现

- 阶段二 `openapi.yaml` 是 `/api/v1` 契约；响应严格使用 `data` 或 `items` 外壳。
- 禁止以任意 `Map<String,Object>` 代替长期输入模型；入参必须 Bean Validation 且拒绝未知字段。
- ID 使用 UUIDv7；时间为 UTC/RFC3339；数据库为 `DATETIME(6)`；金额使用 `BigDecimal`/`DECIMAL(12,2)`，禁止浮点数。
- 写请求必须验证 `expectedVersion` 与幂等键；状态只能由聚合行为转换。

## 7. 异常处理

| 层级 | 可抛异常 | 捕获责任 | 对外映射 | 重试 |
|---|---|---|---|---|
| Domain | `DomainException` | API advice | RFC 7807 + 稳定 code | 不重试 |
| Application | 事务/冲突异常 | Application/API | 409/422/503 | 仅幂等瞬态故障 |
| Infrastructure | JDBC/SDK异常 | Adapter/Application | 不泄露实现细节 | 有界退避 |

禁止吞错、返回伪成功、记录密码/Token/联系方式或无限重试。

## 8. 日志、指标与审计

日志至少包含关联 ID、actorId（可脱敏）、operation、result、duration；安全决定、审核、定价和配置变更写不可变审计记录。禁止记录 Refresh Token、JWT、密码 Hash、完整联系方式和文件签名 URL。

## 9. 并发与异步

核心写使用数据库事务和乐观版本；Refresh 轮换必须加锁并检测重用；消息消费使用 `tn_event_consumption` 去重，Outbox 与业务事实同事务。所有 I/O 设置超时，线程池有界。

## 10. 数据访问

只使用参数化查询；Repository 以聚合根为边界；禁止万能 DAO、跨域写联表和深分页。迁移脚本追加不改写，表名必须通过 `DatabaseNamingTest`。MySQL 是唯一业务事实源，内存仅可作测试替身或可丢缓存。

## 11. 安全编码

密码使用 Argon2id；Access Token 短期且仅内存；Refresh Cookie 必须 HttpOnly/Secure/SameSite，刷新与退出校验 Origin 和双提交 CSRF。授权在后端实施且对象级拒绝不泄露存在性。密钥仅来自环境变量；上传联合验证扩展名、MIME、Magic Number、大小和 Hash。

## 12. 性能与资源

列表必须有界分页；避免 N+1；连接和流使用自动关闭；缓存只保存可重建数据。性能偏离必须以查询计划、指标或压测证据说明。

## 13. 注释与开发文档

注释解释决策与约束，不复述代码。公开端口、复杂状态机、兼容处理和临时方案必须记录原因、移除条件和问题编号。

## 14. 测试规则

测试与源文件同模块镜像放置，使用 `*Test` 命名和 Given/When/Then 或 AAA。领域测试不得访问网络/真实数据库；基础设施集成测试使用隔离实例。关键状态转换、授权、幂等、令牌轮换、金额和时间边界必须覆盖。
