## 4 专家意见

### 4.1 做得好的方面

- PRD 的 40 个原始 FR 编号已全部进入 SRS，并保持原始语义。补充需求使用 `FR-RBAC`、`FR-CFG` 或原域的新编号，不再覆盖源编号。
- 账号、内容、需求、审核和文件五组状态机已写入需求基线，免费内容和收费内容的发布分支也已明确。
- 点赞收藏、注销、通知偏好和专家证据等 P1 能力进入单独延期表，没有被误算为 V1 Core。
- 用户故事保留固定卡片标签和完整验收场景，Task 依赖改用完整 US 或 Task 编号，可直接用于设计和排期。
- 121.5 人天 ROM 明确区分角色工作量与日历工期，并说明了较 v0.1 增加 2.0 人天的原因。

### 4.2 必须处理的问题

- `REQ-ISSUE-005` 已解决：v0.1 重分配了多个 PRD 编号，造成 `FR-CNT-04`、`FR-DMD-04/05`、`FR-PRC-02/03/04`、`FR-LOOP-03` 和 `FR-AIOPS-02/03/04` 等编号语义错位。v0.2 已恢复源编号语义。
- `REQ-ISSUE-006` 已解决：v0.1 漏列 `FR-CAT-01`、`FR-RCM-01`、`FR-MSG-02`、`FR-AIOPS-03/04`，并缺少完整状态机、正式环境可用性、核心 SQL、UTC 和分页要求。v0.2 已补齐。
- `REQ-ISSUE-007` 已解决：v0.1 的 Task 依赖使用“01”“前置 US”等局部表述。v0.2 的 53 个 Task 均使用可识别的 US 或 Task 编号。
- `REQ-ISSUE-008` 已解决：v0.1 通用完成定义未完整覆盖 PRD 第 18 章。v0.2 已补齐权限、数据、错误、安全、日志、测试、API 文档、数据库迁移和可观测性条件。
- `REQ-ISSUE-009` 已解决：v0.1 虽引用系统参数、Feature Flag 和分类约束，但没有对应验收场景和 Task。v0.2 新增场景及 2.0 人天，ROM 调整为 121.5 人天。

### 4.3 改进建议

- `REQ-ISSUE-002` 按已接受的延期计划，在 02 阶段记录个人服务器 CPU、内存、磁盘、网络和基础压测结果，再确定 Alpha 并发、QPS 和数据量阈值。
- `REQ-ISSUE-003` 按已接受的延期计划，在 02 数据库设计评审前确定用户、审核、操作日志、备份和正式文件的保留及删除规则。
- 121.5 人天 ROM 应在 02 设计完成后依据复用组件、外部服务和实际接口数量重估，再形成单人执行的日历计划。

### 4.4 红线风险

无当前阶段红线。个人服务器单点、异地备份和恢复能力仍是上线前红线候选；如果 04 阶段仍没有异地副本和已验证恢复步骤，不应进入真实用户上线。
