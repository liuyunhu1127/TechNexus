## 1 文档目的

本文档把 TechNexus PRD V4.0 和产品发展规划 V1.0 统一为可设计、可开发、可测试的 V1 需求基线。目标读者是产品负责人、设计人员、开发人员、测试人员和早期运营人员。本文覆盖个人服务器 Alpha 至小规模 Beta 所需的产品闭环，并保留长期容量演进边界；不把规划中的支付、复杂即时通信、视频和微服务能力提前纳入 V1 Core。

## 2 业务背景与目标

### 2.1 现状与痛点

现有技术社区通常止于讨论和文章，服务平台通常从已经成形的任务开始，交付结果也很少回到公共知识体系。用户从模糊技术问题到可执行方案之间存在信息断点，服务者的能力缺少可追溯证据，相似问题因此被重复分析和解决。

TechNexus 当前由一名开发者负责产品、研发、测试、运维和早期运营，AI 用于辅助重复工作，个人服务器用于 Alpha 和小规模 Beta。范围、运营步骤和基础设施必须与这一资源条件相符。

### 2.2 目标与成功指标

| 目标编号 | 目标 | 衡量指标 | 当前基线 | 目标值 | 验证时间 |
|---|---|---|---|---|---|
| OBJ-001 | 验证问题到知识的闭环 | 可审计的 Problem 到 Demand 到 Solution 或 Knowledge 完整链路数 | 待首次测量 | 90 天内至少 1 条完整链路 | 2026-12-13 |
| OBJ-002 | 获得真实问题和需求 | 有效问题数和有效需求数 | 待首次测量 | Internal Alpha 取得不少于 10 个有效问题和 3 个有效需求 | 2026-12-31 |
| OBJ-003 | 让单人运营能够处理核心待办 | 待审核、待定价和失败任务的可识别率 | 无统一入口 | 核心待办均可在管理端筛选和处理，高风险决定全部由人工确认 | Alpha 验收 |
| OBJ-004 | 控制早期数据与安全风险 | 备份成功率、异地副本、恢复演练、未授权访问测试 | 待部署测量 | 每日数据库备份、至少一份异地副本、恢复步骤验证通过、关键 IDOR 用例全部通过 | Alpha 上线前 |
| OBJ-005 | 建立可演进的技术基线 | 当前容量压测和长期设计审查 | 待设计与压测 | 当前环境按确认后的 Alpha 指标通过压测；架构不阻断 10 万注册用户和 300 QPS 短时峰值的演进目标 | 设计评审及上线前 |

### 2.3 非目标

- 不在 V1 Core 建设支付、订单结算、自动分账、提现和完整访问权益体系。
- 不建设复杂即时通信、直播、视频转码和自由报价市场。
- 不建设大规模个性化推荐、依赖 AI 的自动审核决策或面向用户的通用 AI Agent。
- 不因技术偏好拆分 Spring Cloud 微服务或引入 Kubernetes。
- 不在冷启动阶段同时运营大量一级技术分类。
- 不承诺个人服务器具备正式商业级高可用 SLA。

## 3 系统范围与边界

### 3.1 范围内

- 用户注册、登录、会话撤销、账号状态和 RBAC 权限。
- 帖子、技术文档、评论、标签、内容版本、可见性和审核。
- 技术问题到结构化需求的创建与来源关联。
- 需求发布、审核、平台评估和定价、方案提交、状态跟踪和自动过期。
- 需求到解决方案或知识对象的来源关系数据模型。
- 统一审核、文件安全、短期授权访问、站内通知和基础搜索。
- 管理后台待办、批量运营、系统参数、Feature Flag 和审计日志。
- AI 标签、摘要、分类、需求结构化和审核原因建议，最终决定由人工作出。
- 单机 Docker Compose 环境的 HTTPS、备份、恢复和基础可观测性要求。

### 3.2 范围外

- 支付、订单交易、自动结算、会员和对外开放的付费访问权益。
- 完整交付协作空间、争议仲裁和服务者市场治理。
- 视频上传、转码、直播和 CDN 媒体体系。
- 私信和复杂即时通信。
- 完整专家能力证据主页及评价体系。
- Elasticsearch 或 OpenSearch 的生产化接入，除非 MySQL 搜索已达到迁移触发条件。

### 3.3 系统上下文

| 外部参与方或系统 | 输入 | 输出 | 交互方式 | 责任边界 |
|---|---|---|---|---|
| 游客和注册用户 | 账号信息、问题、文章、需求、评论 | 公开内容、审核状态、需求状态 | Web 与 HTTP API | 用户对提交内容及授权范围负责，平台负责鉴权与审计 |
| 技术服务者 | 方案、技术栈、周期和建议报价 | 需求信息、方案状态 | Web 与 HTTP API | 仅访问公开或已授权的需求信息 |
| 审核及运营人员 | 审核决定、定价、上下架和配置 | 待办、证据和审计记录 | 管理端与 HTTP API | 高风险决定不得由 AI 自动提交 |
| MySQL | 业务写入和查询 | 核心业务事实 | 数据库协议 | 是用户、权限、审核、价格和状态的最终事实源 |
| Redis | 缓存、限流、幂等和计数 | 可重建的性能数据 | Redis 协议 | 不作为核心业务唯一事实源 |
| MinIO 或兼容对象存储 | 文件对象、上传凭证 | 对象和短期访问地址 | S3 兼容协议 | 应用保存元数据、关系和授权规则 |
| AI 服务 | 待分析文本和提示 | 建议标签、摘要、结构化草稿 | 受控服务接口 | AI 输出仅是建议，不得覆盖事实数据 |
| 邮件或外部通知服务 | 通知任务 | 可选外部通知 | 条件接口 | V1 必须有站内通知，外部渠道不是 Core |

## 4 干系人与用户角色

| 角色 | 目标 | 主要任务 | 权限边界 | 关注点 |
|---|---|---|---|---|
| 游客 | 发现可信内容和公开需求 | 浏览、搜索、注册 | 只读公开资源 | 页面可达性与 SEO |
| 注册用户 | 提问、互动并发布真实需求 | 发帖、评论、发布需求、上传文件 | 只能修改自己的资源 | 隐私和状态透明度 |

| 运营管理员 | 维护供给质量和运营规则 | 定价、推荐、上下架、批量操作 | 运营范围，不管理全局权限 | 待办、审计和误操作控制 |

## 5 业务流程

### 5.1 当前流程

用户在外部社区获得零散建议；需要落地时转到另一服务渠道；交付完成后缺少结构化来源关系和知识沉淀。服务过程和知识内容无法互相建立可信证据。

### 5.2 目标流程

1. 用户创建问题或技术内容，系统保存所有者、可见性和内容版本。
2. 内容进入统一审核；审核员依据明确原因编码通过或拒绝。
3. 用户或管理员从问题创建关联需求，补全技术要求、预算、期限和隐私信息。
4. 需求通过审核和平台评估后发布，技术服务者提交方案。
5. 发布者确认方案后推进执行状态；V1 可由平台线下协调交付，不创建正式订单。
6. 完成的需求关联解决方案或知识对象，保留问题、需求、方案和知识的来源链。
7. 系统通过搜索、内容展示和管理端待办支持复用与运营。

异常流程包括审核拒绝后修改重提、作者撤回未处理任务、需求过期或取消、内容下架、文件扫描阻断、并发编辑冲突和会话撤销。

### 6.3 核心状态机

账号状态只允许以下转换：`REGISTERED → ACTIVE`、`ACTIVE → LOCKED 或 DISABLED`、`LOCKED 或 DISABLED → ACTIVE`、`ACTIVE → CANCELLED`。任何未列出的转换默认拒绝。

| 内容当前状态 | 操作 | 操作者 | 新状态 | 关键规则 |
|---|---|---|---|---|
| DRAFT | 提交审核 | 作者 | PENDING_REVIEW | 冻结本次待审版本 |
| PENDING_REVIEW | 审核通过 | 审核员 | PUBLISHED 或 WAITING_PRICING | V1 免费内容直接发布；P1 启用收费模式后，收费内容等待定价 |
| PENDING_REVIEW | 审核拒绝 | 审核员 | REJECTED | 必须保存原因编码和说明 |
| PENDING_REVIEW | 撤回 | 作者 | DRAFT | 仅任务尚未完成时允许 |
| WAITING_PRICING | 设置最终价格 | 运营 | PUBLISHED | 写入价格历史 |
| PUBLISHED | 修改核心内容 | 作者 | PENDING_REVIEW | 线上继续展示上一发布版本 |
| PUBLISHED | 管理下架 | 运营或超级管理员 | OFFLINE | 必须记录原因 |
| OFFLINE | 重新发布 | 运营或超级管理员 | PUBLISHED | 根据内容变化决定是否重审 |

| 需求当前状态 | 操作 | 操作者 | 新状态 |
|---|---|---|---|
| DRAFT | 提交 | 发布者 | PENDING_REVIEW |
| PENDING_REVIEW | 通过 | 审核员 | APPROVED |
| PENDING_REVIEW | 拒绝 | 审核员 | REJECTED |
| APPROVED | 完成平台定价 | 运营 | PUBLISHED |
| PUBLISHED | 开始沟通 | 系统或参与者 | NEGOTIATING |
| NEGOTIATING | 确认方案 | 发布者 | CONFIRMED |
| CONFIRMED | 开始执行 | 服务流程 | IN_PROGRESS |
| IN_PROGRESS | 提交交付 | 服务者 | DELIVERED |
| DELIVERED | 确认完成 | 发布者 | COMPLETED |
| PUBLISHED 或 NEGOTIATING | 到期 | 系统 | EXPIRED |
| 任一非终态 | 取消 | 有权限操作者 | CANCELLED |
| 任一公开状态 | 管理下架 | 运营或超级管理员 | OFFLINE |

审核任务只允许 `CREATED → PENDING → PROCESSING → APPROVED 或 REJECTED`，并在符合撤回规则时允许 `PENDING 或 PROCESSING → CANCELLED`。文件只允许 `UPLOADING → UPLOADED → SCANNING → AVAILABLE 或 BLOCKED`，TEMP 文件绑定业务后转为 AVAILABLE，超过保留期后转为 EXPIRED 或 DELETED。
