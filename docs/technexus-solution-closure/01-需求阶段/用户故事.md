## 1 估算口径

- 人天表示投入工作量，不等同于日历工期。
- 每个 Task 只归属一个用户故事，避免重复计算。
- 估算包含实现、开发者自测、必要的单元或集成自动化以及文档更新。
- 估算不包含 02 阶段正式设计、04 阶段独立系统测试与性能安全测试、种子内容生产和个人服务器硬件采购。
- 当前是需求阶段 ROM 估算，默认误差为正负 35%。需求、架构或外部服务变化后必须重估。
- 角色人天按前端、后端、测试安全、产品运营和运维拆分。当前一人可承担多个角色，角色拆分不代表多人并行承诺。

## 4 用户故事

### US-001 安全注册登录和会话撤销

#### 4.1 描述

【AS】注册用户  
【I want】注册、登录、刷新和主动退出，并在安全事件后撤销已有会话  
【so that】我能持续访问授权资源且失效凭据不能继续使用

#### 4.2 验收标准

**场景 1 正常登录和刷新**  
【Given】用户账号为 ACTIVE 且凭据有效  
【When】用户登录并在 Access Token 到期前提交有效 Refresh Token  
【Then】系统签发新会话凭据并记录会话标识和到期时间

**场景 2 锁定账号和越权会话**  
【Given】账号为 LOCKED、DISABLED 或 CANCELLED，或会话已被撤销  
【When】客户端尝试登录、刷新或访问受保护接口  
【Then】系统拒绝请求并返回不泄露敏感信息的明确错误

**场景 3 重复退出和失败边界**  
【Given】同一会话已经退出或登录失败达到账号或 IP 阈值  
【When】客户端重复退出或继续尝试登录  
【Then】重复退出返回幂等结果，超限登录被限流且不会创建新会话

#### 4.3 业务规则

1. `[BR-US001-01]` 只有 ACTIVE 账号可以创建新会话。
2. `[BR-US001-02]` 退出、封禁和密码重置必须使相关有效会话可撤销，不能只等待 Token 自然过期。
3. `[BR-US001-03]` 日志不得记录密码、完整 Token 或 Authorization 头。

### US-002 角色权限和对象级鉴权

#### 4.7 描述

【AS】超级管理员和资源所有者  
【I want】平台按 Resource、Action 和 Scope 配置权限并检查对象归属  
【so that】每个角色只能操作被授权的资源和数据范围

#### 4.8 验收标准

**场景 1 正常授权**  
【Given】用户拥有 `article:update:self` 且是文章所有者  
【When】用户更新该文章  
【Then】后端允许请求并保留 owner_id 不变

**场景 2 对象越权**  
【Given】用户没有 `article:update:any` 且不是目标文章所有者  
【When】用户通过修改资源 ID 请求更新他人文章  
【Then】后端拒绝请求且不泄露私有资源内容

**场景 3 重复和高风险变更**  
【Given】管理员准备修改角色权限或重复提交相同授权  
【When】管理员完成二次确认并提交  
【Then】系统幂等保存授权并记录前后值、操作者和结果

#### 4.9 业务规则

1. `[BR-001]` owner_id 只能表示原始所有者。
2. `[BR-US002-01]` 前端菜单和按钮隐藏不能替代后端接口鉴权。
3. `[BR-US002-02]` 无显式授权时默认拒绝。

### US-003 创建帖子和技术文档

#### 4.13 描述

【AS】注册用户或技术创作者  
【I want】用适合技术内容的编辑器保存草稿并提交帖子或文档  
【so that】真实问题和可复用知识能够进入平台审核流程

#### 4.14 验收标准

**场景 1 正常保存和提交**  
【Given】用户具备相应创建权限且必填字段合法  
【When】用户保存草稿并提交审核  
【Then】系统保存内容及版本并创建绑定该版本的审核任务

**场景 2 非法内容和权限**  
【Given】输入含危险 HTML、非法 Mermaid 内容或用户无技术文档发布权限  
【When】用户预览或提交  
【Then】系统清理危险内容或拒绝操作并给出可理解错误

**场景 3 重复提交和字段边界**  
【Given】同一内容版本已经进入审核或标题正文超过限制  
【When】用户重复提交或保存超限内容  
【Then】系统不创建重复审核任务并指出具体字段限制

#### 4.15 业务规则

1. `[BR-US003-01]` 帖子可使用富文本，技术文档优先使用 Markdown。
2. `[BR-US003-02]` 用户输入的 HTML、链接、Mermaid 和公式渲染结果均不可信任。
3. `[BR-US003-03]` 用户优先选择标准标签，新标签进入运营治理流程。
4. `[BR-US003-04]` 首页和运营只突出 AI 应用工程、Java 与 Spring 后端工程、部署与自托管等 2 至 3 个核心方向；后台仍可扩展分类，安全工程为 P1 精选方向。

### US-004 维护已发布内容版本

#### 4.19 描述

【AS】技术创作者  
【I want】修改已发布内容时创建新审核版本  
【so that】读者在审核期间仍能看到稳定的上一发布版本

#### 4.20 验收标准

**场景 1 正常版本切换**  
【Given】内容已有 PUBLISHED 版本  
【When】作者修改正文并且新版本审核通过  
【Then】系统原子切换 current_version 并保留版本和审核历史

**场景 2 拒绝和越权编辑**  
【Given】新版本被拒绝或操作者不是所有者且无 update any 权限  
【When】操作者尝试发布或编辑  
【Then】旧版本继续展示，非法编辑被拒绝并留下审计记录

**场景 3 并发与重复审核**  
【Given】两个编辑基于同一旧版本提交或审核结果被重复提交  
【When】系统处理后到达的请求  
【Then】系统返回 409 或幂等结果，不覆盖较新版本和审核结论

**场景 4 免费和收费内容分支**  
【Given】V1 内容为免费，或 P1 已通过 Feature Flag 启用收费模式  
【When】审核员通过该版本  
【Then】V1 免费内容直接进入 PUBLISHED；仅在 P1 启用收费模式后，收费内容进入 WAITING_PRICING

#### 4.21 业务规则

1. `[BR-002]` 标题、正文和关键附件变化必须重新审核。
2. `[BR-US004-01]` 被拒新版本不得改变 current_version。
3. `[BR-US004-02]` 标签、分类和仅删除附件是否免审由配置决定并可审计。
